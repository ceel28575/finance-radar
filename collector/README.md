# MX 采集与云端同步

旧版首次启用自动升级：若当前 `collector` 文件夹中还没有 `update.bat`，先下载 [update.bat](https://raw.githubusercontent.com/ceel28575/finance-radar/main/collector/update.bat) 并保存到当前 `collector` 文件夹；此后只需双击它即可。它会自动下载最新更新脚本与源码。

1. 首次安装运行 `setup.bat`（已安装的依赖可复用）；后续升级先关闭采集器及其打开的 MX 浏览器，再双击 `update.bat`，程序会自动下载 GitHub 最新代码、备份本机数据、保留登录档案/数据库/同步配置/虚拟环境、更新依赖并运行测试，成功后自动启动新版采集器。
2. 在私有网站的「采集与设置」下载 `cloud-config.json`，放在本目录，不要改名。
3. 关闭旧采集器及它打开的浏览器后，运行 `start.bat`。在程序打开的 MX 网页手动登录。登录会话仅保存于本机 `mx_profile`。
4. 每 60 秒导出本机 SQLite 资料，并同步新增/变更记录到私有网站；网络失败下次重试。本机无配置时仅导出，正常采集不受影响。
5. 同步成功会显示资讯及 AI 报告上传数量。网站每 60 秒读取云端，可在「采集与设置」检查最近同步时间与各日记录数。
6. 启动采集器时会隐藏提示输入豆包 API Key；也可在启动进程前设置 `ARK_API_KEY` 环境变量。程序启动时会先用实际生产接口、模型名和同一 HTTPS 传输方式做一次短请求验证，验证成功后才启动 AI worker；密钥只保存在本次进程内存，不写入配置文件、日志或 GitHub。不要把密钥发给任何人。
7. 双模型分析自动运行：本地 Ollama `qwen3.5:4b` 负责资讯分类、摘要、公司名称和事实提取；豆包 `doubao-seed-evolving` 负责指数多空概率、盘面总结、风险及有来源依据的候选股。Ollama 需在本机运行，模型可用 `OLLAMA_MODEL` 覆盖。
8. A 股交易时段每 60 秒检查，11:30–13:00 午休跳过；15:10 后及非交易时段正常每 30 分钟检查。若本地千问还有待处理队列，则每 5 秒继续一批，全部处理完才调用豆包生成完整报告和下一交易日股票池；模型故障 120 秒后重试。股票池（包括空池）一经收盘生成即冻结，盘中报告沿用当天固定股票池。周末的下一交易日按周一处理；未接入交易所节假日日历，节假日需人工核对。

`update.bat` 会将本机备份保存到 `%LOCALAPPDATA%\FinanceRadar\backups\时间戳`。若更新失败，可从备份目录恢复程序文件；不要上传登录档案、数据库或同步配置。

## 当前边界
- 采集按每轮启动时间间隔 60 秒调度；若 135 个房间的扫描超过 60 秒，下一轮会在本轮结束后尽快启动，不再额外空等完整一分钟，因此不能保证每个房间一分钟内全部刷新。历史未追平的房间会在 SQLite 保存最旧消息游标，后续扫描从上次边界继续回补；已追平房间只读取当前可见的新消息，不会每轮重复加载整段历史。
- 同名房间不再整组跳过：点击时优先使用 DOM 中可识别的 room ID；没有稳定 ID 时按当前快照 DOM 序号定位，并复核房间名与最新消息时间。新增 SQLite 持久化身份映射：首次识别时沿用旧 DOM room key，之后即使房间列表排序或房间名称变化，也按稳定 ID 复用原 key，避免历史消息重复入库；若 MX 未暴露稳定 ID 或多个房间暴露相同 ID，仍退回 DOM 序号并提示实机核验。日期仅为时分的消息使用原采集器推算规则，网页标注待核实。
- 图片链接和原始记录保留；本机检测到 Tesseract 且安装 `chi_sim` 语言包时，会在本地下载 MX 图片并 OCR，提取文字加入分析正文；每轮完整房间扫描最多处理 120 张新图片（跨房间共享预算，避免 100+ 房间导致 CPU OCR 过载），已成功 OCR 的结果缓存在 SQLite，不重复识别；积压图片会在后续扫描轮次继续处理。未检测到 Tesseract、图片无法读取或 OCR 无文字时，图片仍保留并标记待识别。可通过 `TESSERACT_CMD` 指定 tesseract.exe 完整路径。
- 双模型 AI 已加入采集器：本地 Qwen 预处理、云端 Doubao 生成研判；明确公司名与“买/买入/低吸”或“高抛/卖/卖出”同句出现时，另有带原文 ID 的动作候选兜底；最新明确动作优先，否定表达及同句双向策略不机械归类。报告与 AI 引擎状态随云端同步上传；网站还会显示 Ollama 当前是否使用 GPU 及其 VRAM 分配量（以 Ollama `/api/ps` 实际返回为准），并显示房间扫描进度、历史回补积压、重复房间数和定位失败数。收盘后只有在本轮房间扫描与历史回补完成后，才冻结次日股票池。AI 运行失败不会停止 MX 采集与原始数据同步。
- 股票池按原文交易动作识别，不要求大V写出“看多/看空”：针对具体标的出现“买/买入/低吸”归看多，出现“高抛/卖/卖出”归看空；否定表达和“高抛低吸”等双向策略结合上下文处理。模型报告必须提供原文 ID 作为证据，证据不足的股票不进入股票池。
- 盘中报告可随新证据更新；千问处理完当日队列后，收盘后生成并冻结下一交易日股票池；空池也会冻结，避免盘中刷新改变既定股票池。
- 云端按带时区时间换算北京时间日期，相同 ID 更新；屏蔽奇幻团课/qmxp2077。
- 配置含私有网站访问凭据，只用于你自己的电脑。程序仅向固定项目网址发送，禁止重定向。无需提供 MX 密码给网站。
- `mx_cloud.db` 只记录成功接收的内容指纹。失败数据仍在本地；不将失败上传标为成功。
